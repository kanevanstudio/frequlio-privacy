Frequlio Privacy Policy

Effective date: November 23, 2026
Applies to: the Android app “Frequlio” (package name com.frequlio.wifitools)
Developer: KaneVan Studio

Summary

  • Frequlio does not require an account.
  • Frequlio does not send your data to the developer. The developer operates no server for this app.
  • Frequlio contains no ads and no third-party analytics, tracking or crash-reporting SDKs.
  • Diagnostic records are stored only on your device, and you can delete them at any time.

1. Information the app accesses

Nearby Wi-Fi information

When you use the Wi-Fi analysis feature, the app reads Wi-Fi scan results from the Android system. These include the network name (SSID), access point identifier (BSSID), signal strength, frequency, channel, channel width and security type of nearby access points, plus the same details and the link speed of the Wi-Fi network you are connected to. On Android 11 and later, the app also reads the load and capabilities that access points declare in the scan results (for example connected device count, channel utilization, spatial streams, and declarations such as roaming, PMF and WPS).

This information is only shown on screen and used on the device to compute the channel chart and channel suggestions. The app does not save it to storage and does not transmit it anywhere. It is not kept after you leave the screen or close the app.

Current network details

The home screen shows details that Android provides about your current network: connection type, the system’s connectivity validation status, IP addresses, DNS servers, default gateway, network interface name, search domains and MTU. These are only shown on screen. They are not saved or transmitted.

Diagnostic targets you enter, and the results

When you run a ping, a traceroute, a TCP connection test, a DNS lookup or an HTTP/HTTPS diagnosis, the host name, IP address or URL you enter and the measured results (such as resolved IP addresses, timings, HTTP status code and the time of the test), together with the type of network tested (Wi-Fi, mobile data, or that it followed the system; the Wi-Fi name is not saved), are saved as a diagnostic record in the app’s database on your device. Continuous Monitor saves a summary only when you tap Save summary after stopping it: the statistics for each target (attempts and successes, failure reasons, and min/avg/max timings), not the second-by-second results.

When you run a one-tap diagnosis, the result of each step (such as passed or failed, median timings and the HTTP status code) and the local IP address of your router (default gateway) are also saved as a diagnostic record.

For HTTP/HTTPS, only the scheme, host and port of the URL are saved; the path and the query string (the part after ?) are removed, because either may contain tokens. Raw error messages reported by the system are not saved.

App settings

Your chosen theme mode (follow system, light or dark), app language (follow system, Traditional Chinese or English) and Wi-Fi page display settings (hide BSSID, hide weak networks) are stored on the device.

2. Location permission

Android requires an app to hold the precise location permission, and requires the device’s location service to be turned on, before the app can read the list of nearby Wi-Fi networks. Android requires this because nearby Wi-Fi information can technically be used to estimate where a device is.

Frequlio uses this permission only to read Wi-Fi scan results. The app does not request your location coordinates from the system, does not derive, store or transmit your location, and does not use the permission in the background.

The app asks for this permission only when you open the Wi-Fi analysis screen and tap the button to grant it. The other features work without it. You can revoke the permission at any time in Android’s system settings.

3. Network requests the app makes

The app makes network requests only when you run a diagnostic yourself:

  • Ping: sends ICMP echo request packets to the host or IP address you enter and waits for replies.
  • Continuous Monitor: for each target you add (up to 5), sends one ICMP echo packet or makes one TCP connection every second until you stop it, for up to 30 minutes. It runs only while the app is open and this screen is shown.
  • Traceroute: sends ICMP echo packets with an increasing time-to-live (TTL) to the target you enter; each router along the path may see them and report back. The record keeps the addresses of the routers that reported. On Android 11 and earlier, the same packets are sent through the system’s built-in ping command. On Android 10 and later, by default the app also asks the DNS servers of the network used for the test for the names of these router addresses (you can turn off “Look up host names” on the Traceroute screen); any names found are kept together with the addresses.
  • TCP connection test: opens a TCP connection to the host and port you enter, then closes it.
  • DNS lookup: asks, through the Android system, the DNS servers configured for your current network to resolve the domain you enter (on Android 10 or later, it can also look up record types such as MX and TXT, or look up the name for an IP address).
  • Compare with Google Public DNS: only when you tap "Compare with Google Public DNS" below a DNS lookup result, the name and record type you just looked up are sent to Google Public DNS (dns.google) over DNS-over-HTTPS. Google receives them and can see your connection’s IP address. According to Google Public DNS’s privacy notice, temporary logs that include IP addresses normally enter deletion within 24 to 48 hours, may be kept longer to handle security or abuse issues, and sampled permanent logs with the IP address removed are also kept. The comparison is shown on screen only and is not saved to history. Known local and internal names (for example .local names or reverse lookups of private IP addresses) are never sent.
  • Global Ping: only when you tap "Start test" in Global Ping, the target you enter (a domain or IP address) and the selected regions are sent to Globalping (api.globalping.io), whose probes in those regions send ICMP pings to the target; the test does not run from your device. Globalping can see your connection’s IP address and uses it to count the test quota. Under Globalping’s terms, test targets and results are public: anyone with the measurement ID can view them, Globalping may publish, index or analyze them, and copies made by others cannot be deleted. Do not enter internal or confidential hostnames; known local and internal names and private IP addresses are never sent. Results are shown on screen only, and Frequlio does not save them to history. How Globalping handles this information is governed by its terms and privacy policy (globalping.io/terms).
  • HTTP/HTTPS diagnosis: sends one HTTP request to the URL you enter and reads the response status. It does not download the content and does not follow redirects.
  • One-tap diagnosis: opens TCP connections to your router (default gateway), then contacts fixed Google test targets: a TCP connection to 8.8.8.8, a lookup of connectivitycheck.gstatic.com through the system DNS, and one HTTPS request to https://connectivitycheck.gstatic.com/generate_204. Google can therefore see your IP address; how it handles that information is governed by Google’s privacy policy.

These requests go to the target you specify, to the fixed targets of the one-tap diagnosis, to the DNS service your network uses, to Google Public DNS when you choose to compare, and to Globalping when you use Global Ping. As with any network connection, the target service, your network operator or equipment along the path may learn connection information such as your IP address. How they handle it is governed by their own policies and is outside this app’s control.

Apart from diagnostics that you start, the app does not connect to any server on its own.

4. Where data is stored and for how long

  • Diagnostic records and app settings are stored only on your device.
  • At most 500 diagnostic records are kept. When the limit is exceeded, the oldest are deleted automatically.
  • Records remain until you delete them, clear the app’s data or uninstall the app.
  • The app has turned off Android cloud backup and device-to-device transfer, so records and settings do not leave your device through those two channels.

5. Data sharing

The developer does not receive your data, and therefore does not sell, share or disclose it to any third party.

The app lets you export diagnostic records to a CSV or TXT file. An export happens only when you start it, and the file is saved to the location you choose in the system file picker. Exported files are yours to manage. Deleting records inside the app does not delete files you have already exported.

When you tap "Copy" or "Share", that diagnostic result is copied to the clipboard as text, or handed as text to the app you pick in the system share sheet. What happens next depends on the app you pick.

6. Third-party components

The app uses open-source libraries for its interface, network connections and local storage (the list is available in the app under Settings → Open-source licenses). These libraries run on your device and do not collect your data for their developers.

If you install the app from Google Play, Google may process installation and device information under its own policies. That processing is governed by Google’s privacy policy.

7. Managing your data

  • Delete records: in the app, under Tools → History, delete records one by one or all at once, or use Settings → Clear diagnostic records.
  • Revoke the location permission: in Android, under Settings → Apps → Frequlio → Permissions.
  • Delete everything: clear the app’s data or uninstall the app. All data the app stored on the device is removed.

Because the developer holds none of your data, there is nothing further to request deletion of from the developer.

8. Children

The app does not collect personal data from any user, including children.

9. Changes to this policy

If the way the app handles data changes, this policy will be updated accordingly and the effective date above will be revised.
